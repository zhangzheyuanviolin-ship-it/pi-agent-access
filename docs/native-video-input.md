# Native video input

Video understanding is selected-model capability, not a tool preset or opt-in conversation type. The host registers `createVideoAnalysisExtension` once in every resource-loader branch (legacy project, capability-managed, chat workspace, chat-only, subagent). Supported provider/model pairs come from the private `pi-web-context/video-models.json` route allow-list. `session_start`, `model_select`, and `before_agent_start` reconcile the one video tool without changing historical messages or injecting per-turn dates.

`video_analyze` sends the actual file as an OpenAI-style `video_url` data URI to the selected provider. It does not use the MiniMax skill, pre-identify frames, or switch to another provider. Ordinary `read` recognizes common video suffixes and takes the same native path rather than decoding binary as UTF-8. Non-video reads retain the SDK definition, arguments, output contract and implementation. No `video` enum is added to the SDK's text/image-only model schema.

Chats and sessions with general filesystem capability disabled retain a path admission check: a video must have been explicitly named/uploaded by the user in that conversation. This does not expose a shell, writes or arbitrary files. General tool presets cannot silently remove native video capability. Models without a verified native route do not expose the video tool and reject binary video reads clearly.

The current bounded request path supports files up to the route's configured capacity (80MiB maximum), validates video tracks with ffprobe, preserves the source file and its duration, and forwards cancellation. Upload storage capacity is distinct. Large-file segmentation and arbitrary codecs are not certified here. oMLX 0.7.3 samples at most 64 frames per clip; accepting a whole video file does not mean processing every source frame. A 199.96-second clip in the November 2 acceptance sampled 64/5199 frames. Model-generated counts, OCR and timestamps can be wrong; the tool passes authoritative container duration and asks the model not to fabricate exact timings.

The first request after adding this previously missing tool may legitimately have a new tool-prefix fingerprint. Subsequent ordinary turns retain the same definitions and append-only user/tool messages. A video analysis adds only its actual tool result, not a rewrite of prior history. Test evidence lives outside the repository, without keys or embedded video payloads.

Validation: node --test lib/video-autoload.test.mjs lib/video-analysis.test.mjs lib/context-capabilities/managed.integration.test.mjs lib/received-attachments.test.mjs. Production acceptance must include an ordinary unmanaged session, UI upload at desktop/mobile widths, read(video), a chat-only session, capabilities disabled, model switching, and follow-up cache statistics. A synthetic short fixture alone is insufficient to certify a user's longer clip or recognition quality.
