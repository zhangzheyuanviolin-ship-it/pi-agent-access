# 稳定版本发布验收约定

这是一项开发发布约束，不是新增的用户审批界面。新功能不能以其他已有功能失效为代价。每次发布前读取当前完整交接和历史故障证据，按实际安装模型清单逐个检查，任何失败、跳过和未验证不能当作通过。

发布材料必须绑定本次源代码指纹、实际Git提交、模型清单、关键引擎校验值和真实测试证据。证据过期或代码变化必须重新审查。scripts/verify-access-release-gate.mjs默认检查24小时内材料，并核对本地证据文件SHA256。package-access-macos.py默认强制执行；development-only仅用于开发，不得作为稳定包公开。GitHub合并上传流程也要求完整releaseGate声明，并核对标签实际提交。不要绕过检查直接手动公开草稿。

固定检查范围包括所有已启用本地后端的真实消息、write/read实际文件和续聊缓存；终端；LCU实际截图、键盘、元素及坐标点击、滚动、浏览器发现、输入和拖放；至少一个真实模型调用同一电脑操作接口。工具出现在列表里不代表已执行成功，必须用动作后的状态回读验证。

视频检查必须通过现有支持型号真实上传MP4并使用该型号原生video_url路径，不能用外部识别文本冒充视觉输入。当前无已接入本地视频模型时，必须实际走云端路径；本地候选接入后追加本地测试。覆盖普通会话、能力预设变化、只读权限、普通read读取视频、手机附件和桌面入口。保留模型识别错误，接口成功不能写成百分百理解正确。

记忆检查覆盖新会话全局记忆默认开启、项目记忆默认关闭、手动关闭与已有选择保持。只对新会话创建固定快照，不改写旧历史和前缀。无能力记录的旧会话不能在一次普通续聊时突然注入新系统段。

DeepSeek4.1专项检查区分GPU上限、全局有线内存、运行时可用内存、启动准入、真正分配失败。至少检查配置有效、冷加载、重复卸载再加载、SSD前缀恢复和资源竞争拒绝。不得因一次内存加载失败就无证据重复提高系统上限，不得用skip-mem-preflight绕过所有检查冒充修复。模型预算、图像模块和DSpark保持明确记录。125GB全局有线额度用于避免音频锁定失败，单独核实，保护旁白优先。

缓存检查覆盖旧提示前缀、附件只追加新用户消息、固定工具与记忆快照、模型切换后恢复、检查点写入完成和真实时间间隔后的续聊。源码没有TTL不能冒充已经等待半小时。MLTF含图历史的SSD持久恢复存在已知上游限制，必须继续明确标注，不能写成已解决。缓存恢复Token数、实际新增预填充、首字等待和解码速度必须分开记录。

浏览器原生连接注册为用户级共享入口，其他应用可能重写。每次质检必须核对注册并真实发现浏览器。已授权普通电脑操作时，Pi仅可用既有官方LCU安装命令恢复原连接器，不改权限，不重启浏览器，不重放动作。需要唤醒扩展时通过当前Chrome界面观察后打开既有扩展，不凭空点击或绕过授权。完全自有浏览器驱动仍为单独工程，不假称已经独立于上游。

禁止为了验收终止旁白、语音、网络代理、用户任务和正在进行的下载。测试结束精确删除自建测试会话；保留用户历史、模型和缓存。安全拒绝真实资源不足、系统权限缺失或其他活动任务是正确行为，不能以取消保护来满足“永不报错”的假目标。检查记录应明确通过范围、剩余限制、失败与重试，不得只保留最好的一次。
