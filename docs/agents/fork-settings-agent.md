# Local v5: opt-in model/settings gateway and permissions

The eighth managed context capability is `admin`, labeled 模型与设置. It is last and defaults false, including v1 records saved before the field existed. Legacy sessions are not silently migrated. `settings_manage` registers only for an enabled managed project session; ordinary Chats retain their existing restrictions. The exact prompt projection remains in `lib/exact-system-prompt.ts`.

`lib/settings-agent/extension.ts` declares one compact schema. `describe(resource)` returns the selected part of `catalog.ts` on demand, rather than injecting every admin interface into the system prefix. Resource/operation allow lists reject General and permissions. No arbitrary API URL/method is accepted. The gateway reuses the existing stores, validators, routes and runtime. Enabling admin does not enable files/plugins/MCP/skills implicitly. Changes to resource selection do not mutate a frozen session snapshot; the user must apply their current capabilities or open another session.

Providers/models use minimal edits to models.json, schema validation in a private temporary runtime, optimistic revision checks, private backups and guarded restore. Existing auth.json and OAuth data are not read into tool results or rewritten. API keys/headers/env/secrets are redacted, while contextWindow/maxTokens remain visible. Executable credential references are rejected. New values supplied in chat or tool arguments are necessarily visible to the current provider and transcript; the UI warns of this. This is not a secret-entry alternative to Settings.

Model switching is queued and performed in agent_end, with a custom outcome entry and notification. Calling another configured model uses the SDK registry's authenticated streamSimple with bounded timeout/output, without returning the auth resolver's key/headers. The current chat bridge supports text/image input and text output. Unsupported audio/video are rejected, not silently converted. Configuration cannot invent an unsupported runtime modality.

Skills can be installed/toggled through the original interfaces; generated/editable documents are constrained to `skills/pi-web-managed/<slug>/SKILL.md`, new skills start disabled. Plugin packages use the original install/update/enable/disable routes, newly installed packages are disabled again before returning. Generated extension code is confined to `extensions/pi-web-managed/<slug>.mjs` and saved disabled. It cannot rewrite the maintained LCU or package contents. Managed standalone enable/disable updates the settings paths and plugin approval; it does not reload a running session. Package installation and code execution remain high-risk operations requiring approval.

MCP uses original add/toggle/remove/undo handling and SDK validation for config updates. Project trust cannot be granted through this gateway and host environment confirmation cannot be manufactured. Scheduled task removal pauses rather than deleting runs. Existing app scheduler behavior applies: app shutdown/sleep affects execution. Subagent profiles use existing helpers; removal disables the profile. Invocation reuses the original controller and its concurrency/settings checks. Child sessions receive the global permission guard but not this admin gateway automatically.

App-scoped environment variables are saved in private mode-0600 local JSON and applied on the next app start as well as this process's future children. This is filesystem privacy, not encryption or Keychain. Proxy/PATH/runtime/security/PI/CODEX settings are reserved. Existing subprocesses do not get new variables retroactively. No shell profiles or launchd global environment are modified.

Permissions live separately in `pi-web-context/permissions.json` and Settings > 权限. Missing file preserves the old full mode; invalid data fails closed to readonly. Guards run for managed, legacy, Chat-only, Chat workspace and child sessions. Read-only allows known read tools or readOnlyHint declarations; unknown tools fail closed. Ask confirms modifying/executing tools, full preserves normal tool behavior. Gateway mutations/external calls always confirm, even in full. This is application tool approval, not an OS sandbox: trusted plugins or an allowed terminal can execute arbitrary local code. It does not revoke macOS TCC permissions or isolate credentials from arbitrary executable code.

Validation: isolated stores and SDK faux provider, all 256 category gate combinations, real packaged HTTP/SSE confirmation flow, explicit image payload forwarding to a local protocol fixture, actual queued SDK model switch, browser/keyboard tests and native AX readback. No paid provider traffic, real credential changes, real plugin downloads, large-model inference or GPU benchmark formed part of these checks.
